# Freelens Kubeconfig Sync Runtime-Add Fix — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix freelensapp/freelens issues #551 and #1108 — kubeconfig file/folder syncs added at runtime via the Preferences UI must start watching and surface clusters immediately, without an app restart, on Windows / macOS / Linux. Add a manual Refresh syncs control as a fallback.

**Architecture:**
- Primary fix: rework the main-process hookup in `KubeconfigSyncManager.startSync()` so that it reacts robustly to runtime mutations of the `kubeconfigSyncs` ObservableMap, regardless of whether the user-preferences IPC layer mutates the map in place or replaces its contents.
- Secondary fix: a "Refresh syncs" button in the Kubeconfig Syncs preferences panel and a `Ctrl+Shift+R` / `Cmd+Shift+R` accelerator that, via IPC, triggers `stopSync()` then `startSync()` on the main process.
- Validation: produce two unsigned Windows installers via a fork-side GitHub Actions workflow (Linux→Windows native cross-build is not supported by this codebase, and wine is not installed locally) — Build #1 from `main` (baseline), Build #2 from the fix branch.

**Tech Stack:** TypeScript, Electron, MobX (`observable.map`, `reaction`, `observe`), `@ogre-tools/injectable` DI, chokidar v4, electron-builder (nsis target), Jest + jest-mock-extended for tests, pnpm workspaces, Turbo, Biome.

## Task 2: Add a fork-side Windows build workflow

**Files:**
- Create: `.github/workflows/build-windows.yaml`

**Why:** WSL→Windows cross-build with electron-builder requires wine, which isn't installed and isn't documented as a supported path for this repo. The official release builds run on `windows-2025` runners. We mirror that minimally: a `workflow_dispatch`-only job that builds the nsis installer for the current branch and uploads it as an artifact. The user pushes their fork, dispatches the workflow, downloads the .exe.

- [ ] **Step 1: Create the workflow file**

Write `.github/workflows/build-windows.yaml`:

```yaml
name: Build Windows test installer

on:
  workflow_dispatch:
    inputs:
      label:
        description: "Label to embed in the artifact name (e.g. baseline, fix)"
        required: true
        default: "test"

permissions:
  contents: read

jobs:
  build:
    runs-on: windows-2025
    timeout-minutes: 90

    env:
      DO_NOT_TRACK: "1"
      ELECTRON_CACHE: ${{ github.workspace }}/.cache/electron
      ELECTRON_BUILDER_CACHE: ${{ github.workspace }}/.cache/electron-builder
      ELECTRON_HEADERS_CACHE: ${{ github.workspace }}/.cache/electron-headers
      # Skip macOS notarization hook on Windows.
      CSC_IDENTITY_AUTO_DISCOVERY: "false"

    steps:
      - name: Checkout
        uses: actions/checkout@v6

      - name: Install yq
        shell: bash
        run: choco install yq --yes --no-progress

      - name: Setup Node
        uses: actions/setup-node@v6
        with:
          node-version-file: mise.toml

      - name: Setup pnpm
        run: corepack install
        shell: bash

      - name: Install dependencies
        run: pnpm install --frozen-lockfile
        shell: bash

      - name: Generate DI registration
        run: pnpm build:di
        shell: bash

      - name: Build packages
        run: pnpm build
        shell: bash

      - name: Build Windows nsis installer (unsigned)
        run: pnpm build:app --win nsis --x64
        shell: bash

      - name: Rename artifact
        shell: bash
        run: |
          set -euo pipefail
          mkdir -p out
          # electron-builder's default nsis name is "Freelens Setup <ver>.exe".
          src=$(ls freelens/dist/*.exe | head -1)
          ver=$(jq -r .version freelens/package.json)
          cp "$src" "out/Freelens-${ver}-${{ inputs.label }}-windows-amd64.exe"

      - name: Upload installer
        uses: actions/upload-artifact@v4
        with:
          name: Freelens-windows-${{ inputs.label }}
          path: out/*.exe
          if-no-files-found: error
          retention-days: 14
```

- [ ] **Step 4: Rewrite `startSync()` to use `reaction()`**

Replace the body of `startSync()` (current lines 53–74) with:

```typescript
@action
startSync(): void {
  this.dependencies.logger.info(`starting requested syncs`);

  // This must be done so that c&p-ed clusters are visible
  this.startNewSync(this.dependencies.directoryForKubeConfigs);

  let watchedPaths = new Set<string>();

  this.syncListDisposer = reaction(
    () => new Set(this.dependencies.kubeconfigSyncs.keys()),
    (currentPaths) => {
      for (const filePath of currentPaths) {
        if (!watchedPaths.has(filePath)) {
          this.startNewSync(filePath);
        }
      }
      for (const filePath of watchedPaths) {
        if (!currentPaths.has(filePath)) {
          this.stopOldSync(filePath);
        }
      }
      watchedPaths = currentPaths;
    },
    { fireImmediately: true },
  );
}
```

Notes for the engineer:

- `fireImmediately: true` replaces the previous "iterate keys() once at startup" loop — the first invocation starts watchers for whatever's already in the map.
- `watchedPaths` is the diff baseline. It starts empty, so the first invocation sees every current key as "added" and calls `startNewSync` for each. Subsequent invocations see only the diff.
- Replacing the whole map with `replace()` produces a brand-new Set from `keys()`, so the diff still works correctly — that's the property `observe()` lacked.
- `directoryForKubeConfigs` is started outside the reaction because it's a constant, not part of `kubeconfigSyncs`; it never needs the diff.
- `startNewSync()` already short-circuits if a path is already watched (lines 88–91), so even if a future caller introduces a duplicate the behavior is benign.

```markdown
## What

Fixes #551 and #1108 — kubeconfig file/folder syncs added at runtime via Preferences → Kubernetes → Kubeconfig Syncs were not registering until the app was force-restarted (Task Manager on Windows, Activity Monitor on macOS).

## Why

`KubeconfigSyncManager.startSync()` used `mobx.observe()` on the `kubeconfigSyncs` ObservableMap to react to runtime mutations. The map is updated via the user-preferences IPC layer, which (per investigation logs) sometimes delivers updates as full-map replacements rather than per-key add/delete events; `observe()` does not fire reliably in that case.

## How

Replace `observe()` with a `reaction()` whose tracked expression is `Array.from(kubeconfigSyncs.keys())`. The reaction body diffs the new keyset against a previously-watched set, calling `startNewSync()` for added paths and `stopOldSync()` for removed paths. Robust to both in-place mutation and wholesale replacement; no platform-specific code.

Also adds:
- A "Refresh syncs" button in the Kubeconfig Syncs preferences panel.
- A `Ctrl+Shift+R` / `Cmd+Shift+R` accelerator that triggers the same action.

These are user-facing fallbacks for cases where the watcher state needs to be manually refreshed.

## Tests

- `kubeconfig-sync.test.ts`: new cases for runtime add, runtime delete, and wholesale replacement.
- `refresh-listener.test.ts`: IPC handler invokes `stopSync` then `startSync`.

## Validated

- Reproduced the bug on Windows 11 with a build of the same commit as the fix's parent (Build #1).
- Verified the fix on Windows 11 with the fix applied (Build #2). All five acceptance criteria pass.

## Risk

The fix touches shared (cross-platform) code. The bug it fixes is also cross-platform (#551 was reported on Windows; the same root cause was confirmed on macOS in [this comment](https://github.com/freelensapp/freelens/issues/551#issuecomment-3165466863)). The reaction-based hookup is strictly more general than the observe-based hookup it replaces: it fires for every case `observe()` fires for, plus the wholesale-replacement case `observe()` missed.
```
